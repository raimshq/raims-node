# Raims Node.js SDK

Read README, CONTRIBUTING, and docs/maintenance.md before changing this SDK.

- Write repository descriptions and Markdown documentation in English.
- Keep internal TODO lists, backlogs, and roadmaps out of this public repository
  and its packages. Track operational work in the private workspace backlog
  maintained outside Git. Do not publish its contents, location, or links.
- Consume only the pinned public contract in contracts, with its checksum and
  immutable revision verified. Do not import private host code or contracts.
- The package targets Node.js 22 or later, ESM and CommonJS modules, and
  TypeScript declarations. It has no production dependencies.
- src/generated/contract.json, types/index.d.cts, types/index.d.mts, and
  docs/reference.md are generated by scripts/generate.cjs. Do not edit them by hand.
- Preserve JSON names, safe integer cents, Unix seconds, omission, and null.
  The SDK does not generate idempotency keys or retry writes automatically.
- Authentication uses an API key. Do not provide environment selection or
  arbitrary headers. Credentials belong on the integrator's backend.
- Preserve structural response validation and future fields. Reject integers
  outside JavaScript's safe range instead of rounding them.
- The transport does not follow redirects, download external links, or upload
  files. Diagnostics contain only method, parameterized path, attempt,
  duration, status, and request identifier.
- Tests, simulators, validation consumers, tools, and evidence belong exclusively
  in C:\server\raims\.tmp\raims-node-sdk. Do not version them.
- `contracts/node-api.json` is the independent public-symbol baseline.
  `npm run check-compatibility` is read-only. A deliberate update uses
  `npm run snapshot-api` and requires diff review; OpenAPI generation must not rewrite it.
- Run `npm run check`, which invokes the canonical Developer Toolkit validator.
  Initial tool preparation uses `npm run check -- --prepare-tools`.
  `npm run check-source` covers only generated outputs and syntax, not full approval.
  Validate HTTP with isolated dependencies only; do not call the real API.
- The npm package contains runtime, types, and integrator guides. Contracts,
  generators, the compatibility baseline, and internal instructions stay out of it.
- Keep changes uncommitted and unstaged. npm publication, remote repository
  creation, pushes, releases, and deployment require their own authorization.
- Describe Raims features directly. Preserve required licenses and attribution
  for incorporated code.
